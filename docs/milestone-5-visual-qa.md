# Milestone 5 production visual QA

This is the repeatable review set for the production UI migration. The approved preview and approved-design images remain the presentation authority; production read models remain the data authority.

## Capture procedure

From the repository root, run `node scripts/capture-production-visuals.mjs`. The script renders the actual production AppShell and screen components using fixed synthetic **test-only** view models, embeds the locally installed IBM Plex font files, fixes the viewport, device scale and theme, disables nonessential motion, and writes PNGs to `docs/regression-reference/production-qa`. It does not enter the production dependency graph or impersonate a signed-in user. Captures are deterministic layout references, not evidence of a successful planner run or a live authenticated session.

Exact pixel comparison is intentionally not the gate: the approved preview contains a full illustrative semester while these production captures use sparse synthetic models, and a real account's canonical facts vary. The Chromium visual-contract test checks 12 screen families at 1440, 1024, 768, 640 and 390 CSS pixels in both themes. It asserts the shell dimensions, lack of horizontal overflow, expected Week transformation, panel visibility, mobile 44 px targets, keyboard focus, Week's semantic list, contrast of small muted text and reduced-motion tokens. Existing route E2E checks preserve browser Back/Forward and the approved-preview E2E remains separate.

Human comparison of these captures found and corrected a top-bar overflow at laptop/tablet widths, a 38 px mobile command trigger, short Week list/deadline links, low-contrast light-theme muted text, and Today's missing desktop context rail. The remaining visual difference caused by sparse test data is expected; do not fill it with preview fixtures. The final literal exit-gate audit should inspect a populated authenticated account in both themes before declaring visual fidelity passed.
